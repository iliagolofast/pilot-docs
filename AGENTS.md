# Инструкция для ИИ-ассистента: документация PILOT

Этот репозиторий — сайт справки по платформе GPS-мониторинга PILOT.
Сайт: https://iliagolofast.github.io/pilot-docs/ (GitHub Pages публикует ветку `main` как есть).

Редактор ставит задачи обычным языком («добавь…», «исправь…», «переведи…»). Твоя задача — внести правку в исходники, при необходимости обновить переводы и собрать сайт.

## Что где лежит

| Путь | Что это | Править? |
|---|---|---|
| `content/` | Статьи на русском (markdown) и картинки. **Источник правды.** | Да |
| `i18n/<язык>/` | Переводы статей: `en`, `uk`, `ar` (справа налево), `es`. Тот же путь, что в `content/`. | Да |
| `i18n/BRIEF.md` | Глоссарий и правила перевода терминов. | Читать перед переводом |
| `gen.js` | Сборщик: `content/` + `i18n/` → `data/`. Тут же список тем-тегов (`TAGS`). | Редко |
| `index.html` | Оболочка сайта: дизайн, поиск, темы, строки интерфейса на 5 языках, интерактивные демо. | Только если просят про дизайн/интерфейс |
| `data/` | **Собранный** сайт (JSON). Руками не править — только через сборку. | Нет |

## Как устроены статьи

- Папка = раздел, `.md`-файл = статья. Текст самого раздела — `index.md` внутри папки.
- Порядок задаёт числовой префикс: `03-kak-dobavit-datchik.md`. Чтобы вставить статью между 03 и 04, сдвинь префиксы соседей (и в `i18n/*` тоже).
- Имена файлов — латиница (транслит), через дефис.
- В начале файла frontmatter:
  ```
  ---
  title: "Как добавить датчик"
  ---
  ```
  Заголовок `# …` в тексте не пишем, он берётся из `title`. Внутри — `##` для разделов, `###` для подразделов.
- Картинки — в папке `images/` рядом со статьёй, формат `.webp` (или `.png`/`.jpg`), ссылка `![описание](images/имя.webp)`.
- Ссылки на другие статьи — относительные, **без числового префикса**, с `.html`: файл `../../06-roli-i-prava-dostupa.md` → `[Роли](../../roli-i-prava-dostupa.html)`; раздел с `index.md` → `папка/index.html`.
- Сложные таблицы можно писать HTML-ом.
- Стиль: русский язык, обращение на «вы», названия кнопок и пунктов меню **жирным**.
- Блоки `<div class="demo" data-demo="…"></div>` в разделе «С чего начать» — интерактивные демо. Не удаляй их.

## Порядок работы

1. Найди статью по теме (поиск по `content/`). Не создавай дубль, если тема уже описана — дополни существующую.
2. Внеси правку в `content/`.
3. Обнови переводы в `i18n/en`, `i18n/uk`, `i18n/ar`, `i18n/es` по тому же пути, соблюдая глоссарий `i18n/BRIEF.md`. Если перевода нет — сайт покажет русский текст с пометкой, это допустимо, но лучше перевести.
4. Собери сайт: `npm ci` (один раз), затем `npm run build`. Сборка должна пройти без ошибок.
5. Закоммить в `main` и `content/`/`i18n/`, и обновлённый `data/`. Сообщение коммита — по-русски, что изменено.

Если собрать нельзя (нет терминала), закоммить только `content/` и `i18n/`: GitHub Action `Сборка сайта` (`.github/workflows/build.yml`) сам пересоберёт `data/` и закоммитит его. Сайт обновится через 1–3 минуты.

## Чего не делать

- Не править `data/` вручную.
- Не удалять и не переименовывать файлы массово без явной просьбы.
- Не менять `index.html` и `gen.js` ради правок текста.
- Не добавлять секреты, пароли, реальные данные клиентов (госномера, телефоны, имена) — репозиторий публичный.
