Во вкладке Statistics отображается статистика передачи данных и информация о возможных ошибках ретрансляции.

Чтобы открыть статистику, перейдите в раздел «Ретрансляция» → «Statistics».

![](images/drex_statistika_custom.png)

Страница позволяет контролировать работу ретрансляции, отслеживать успешность передачи данных, анализировать ошибки и выявлять проблемные объекты или направления передачи.

![](images/drex_statistika_custom_2.png)

Статистика формируется на основе данных сервиса ретрансляции и отображается с учетом прав текущего пользователя.

Администратор может просматривать глобальную статистику по всей системе или статистику по отдельным endpoint.

Пользователь-партнёр видит статистику только по своим endpoint и endpoint партнеров, находящихся ниже в его иерархии.

### Режимы просмотра статистики

Для администратора доступен фильтр Scope:

-   Global (Глобально) — статистика по всей системе ретрансляции.
    
-   Endpoints (Endpoints) — статистика по отдельным направлениям передачи данных.
    

![](images/drex_statistika_custom_3.png)

Пользователи с ролью партнёра работают только в режиме Endpoints.

## Фильтры статистики

В верхней части страницы расположены фильтры, которые позволяют выбрать необходимые данные для анализа.![](images/drex_statistika_custom_4.png)

### Scope (Область статистики)

Определяет источник статистики:

-   Global — статистика по всей системе;
    
-   Endpoints — статистика по отдельным endpoint.
    

Доступно только администраторам.

### Protocol (Протокол)

Фильтр по протоколу передачи данных. Позволяет отображать статистику только по выбранному протоколу.

### Metric (Метрика)

Определяет, какие события будут отображаться в графиках и таблицах.

Доступны следующие значения:

-   All metrics — все метрики
    
-   OK only — только успешно принятые пакеты
    
-   Errors only — только ошибки
    
-   Spooled only — только пакеты, помещенные в очередь
    
-   Dropped only — только отброшенные пакеты
    

### Endpoint

Позволяет выбрать один endpoint или группу endpoint для анализа.

Список endpoint сгруппирован по партнёрам.

### Loop threshold/hour (Порог циклической передачи в час)

Используется для поиска объектов с подозрительно большим количеством передаваемых пакетов.

Если количество пакетов превышает указанный порог, объект может попасть в таблицу Loop suspicion.

### От и до

Начало и конец анализируемого периода.

Время на графиках отображается в локальном часовом поясе пользователя в 24-часовом формате.

## Графики статистики

В верхней части страницы отображаются графики, которые помогают быстро оценить состояние ретрансляции.

**![](images/drex_statistika_custom_5.png)**

### Traffic over time

Показывает изменение количества пакетов во времени.

График помогает определить:

— периоды высокой активности

— резкое увеличение нагрузки

— моменты появления ошибок

— периоды отсутствия передачи данных

### Outcome

Показывает распределение результатов передачи данных.

По графику можно быстро оценить:

— сколько пакетов было успешно принято

— сколько пакетов завершилось ошибкой

— сколько пакетов было помещено в очередь

— есть ли проблемы с передачей данных

![](images/drex_statistika_custom_6.png)

### By protocol

Сравнивает статистику по различным протоколам передачи данных.

График позволяет определить:

— какой протокол используется чаще всего;

— на каком протоколе возникает больше ошибок

— какие протоколы создают основную нагрузку

### By endpoint

Сравнивает статистику между endpoint.

По графику можно быстро определить:

— наиболее активные endpoint

— endpoint с повышенным количеством ошибок

— направления передачи с наибольшей нагрузкой

Если нажать на любой endpoint на графике By endpoint, система автоматически:

— выберет этот endpoint в фильтре

— обновит остальные графики

— обновит таблицы статистики

— покажет информацию только по выбранному endpoint

![](images/drex_statistika_custom_7.png)

## Метрики

В статистике используются следующие показатели.

### Accepted / Ack

Количество пакетов, успешно принятых внешней системой. Чем выше этот показатель, тем успешнее работает ретрансляция.

### Send

Количество попыток отправки пакетов. Показывает общий объем исходящей передачи данных.

### Errors

Количество ошибок отправки или подключения. Рост этого показателя обычно говорит о проблемах со связью, настройками endpoint или доступностью внешней системы.

### Spooled

Количество пакетов, помещенных в очередь на отправку. Такие пакеты будут отправлены позднее, когда передача станет возможной.

### Dropped

Количество пакетов, которые были отброшены сервисом и не будут переданы.

### Queue

Текущий размер очереди endpoint. Если значение постоянно растет, это может говорить о проблемах с отправкой данных во внешнюю систему.

## Таблицы статистики

Под графиками располагаются таблицы с информацией.

![](images/drex_statistika_custom_8.png)

### Top endpoints

Список endpoint с наибольшим количеством переданных пакетов за выбранный период.

Позволяет быстро определить наиболее активные направления передачи данных.

### Recent endpoint errors

Список последних ошибок ретрансляции.

Таблица помогает быстро понять причину проблем с передачей данных и определить endpoint, в котором возникла ошибка.

### Top vehicles for endpoint

Список объектов, которые создали наибольший объем трафика для выбранного endpoint.

Используется для анализа нагрузки и поиска наиболее активных объектов.

![](images/drex_statistika_custom_9.png)

### Loop suspicion

Список объектов, которые превысили установленный порог количества пакетов в час.

Такая ситуация может свидетельствовать о циклической передаче данных, ошибке настройки оборудования или некорректной работе интеграции.

При появлении объектов в этом списке рекомендуется проверить настройки ретрансляции и источник данных.

![](images/drex_statistika_custom_10.png)
