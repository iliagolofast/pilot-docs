Раздел «Ретрансляция» предназначен для передачи данных объектов мониторинга во внешние системы.

Например, данные могут передаваться в:

— городские платформы

— интеграционные сервисы

— системы мониторинга, такие как Wialon

— серверы, работающие по протоколу EGTS

— REST API

— другие внешние системы, принимающие телематические данные

Работа с ретрансляцией построена по такому принципу:

1\. Создайте направление передачи данных (endpoint)

2\. Укажите параметры подключения к внешней системе

3\. Подключите к этому endpoint один или несколько объектов

После этого система начнет автоматически передавать данные выбранных объектов во внешнюю систему.

Такой подход позволяет один раз настроить подключение и использовать его для любого количества объектов без повторного ввода адреса сервера, порта, параметров авторизации и других настроек.

![](images/drex_retranslyatsiya_2_custom.png)

Раздел «Ретрансляция» состоит из трех вкладок:

-   Endpoints — направления передачи данных во внешние системы. Здесь настраиваются параметры подключения к внешней системе: адрес сервера, порт, протокол, данные для авторизации и другие параметры.
    
-   Statistics — статистика передачи данных, информация об ошибках и состоянии передачи. Здесь можно проверить наличие ошибок, посмотреть количество отправленных и принятых пакетов, оценить состояние очередей и убедиться, что данные успешно поступают во внешнюю систему.
    
-   Objects — объекты, подключенные к ретрансляции. К одному endpoint можно подключить любое количество объектов. При необходимости объект можно отключить от ретрансляции или подключить к другому endpoint.
    

## Основные понятия ретрансляции

Ниже приведены основные термины, которые используются в разделе.

### Endpoint

— это направление передачи данных во внешнюю систему.

В endpoint указываются параметры подключения:

-   адрес сервера
    
-   порт
    
-   протокол передачи данных
    
-   путь, если он требуется
    
-   параметры авторизации
    
-   дополнительные настройки
    

Один endpoint может использоваться сразу несколькими объектами. Например, если все объекты должны передавать данные в одну учетную запись Wialon, достаточно создать один endpoint и подключить к нему нужные объекты.

Объект — это транспортное средство, устройство или любой другой объект мониторинга, данные которого передаются через выбранный endpoint. Каждый объект может иметь собственные параметры ретрансляции, например внешний идентификатор или расписание передачи данных.

### Партнёр

— это партнерский договор, которому принадлежит endpoint.

В зависимости от прав доступа пользователь может работать только со своими endpoint или также видеть endpoint дочерних партнеров.

### Договор

— договор конечного пользователя, которому принадлежит объект мониторинга

### Автодобавление объектов (Auto add

) — с помощью этой функции можно автоматически подключать новые объекты выбранного договора к endpoint. Например, все объекты клиента должны передавать данные в одну и ту же внешнюю систему. После настройки правила каждый новый объект, созданный в выбранном договоре, будет автоматически подключаться к endpoint без дополнительных действий пользователя.

### Внешний ID (External ID)

— идентификатор объекта во внешней системе. По умолчанию в качестве External ID обычно используется IMEI устройства, однако при необходимости его можно изменить.

Внешняя система использует этот идентификатор для распознавания объекта и сопоставления получаемых данных.

### Uspw

— данные для авторизации при передаче данных во внешнюю систему. В зависимости от используемого протокола здесь может храниться логин, пароль, токен или другие параметры доступа. Если протокол требует дополнительные параметры авторизации, они указываются в поле Json config.

## Права доступа

Доступные данные и действия зависят от роли пользователя в админпанели.

### Администратор

Администратор имеет полный доступ к разделу и может:

— просматривать все endpoints

— управлять всеми объектами ретрансляции

— создавать, изменять и удалять endpoints

— просматривать общую статистику по всем ретрансляциям

— работать с тестовыми endpoints

### Пользователь

Пользователь-партнёр видит только данные, которые относятся к его партнёрской структуре.

Ему доступны:

— собственные endpoints

— endpoints дочерних партнёров

— объекты договоров, входящих в доступную партнёрскую ветку

— статистика по доступным endpoint

Партнёр не может просматривать или изменять данные, относящиеся к другим партнёрским структурам
