The “Settings” tab contains parameters that the system administrator configures through special configurations. Configurations are ready-made sets or templates of settings that the administrator can apply to objects. To learn how to add an object settings configuration through the admin panel, see [here](../../../panel-administratora/dogovor/konfiguratsiya/konfiguratsii-dlya-nastroek-obekta.html).

The “Settings” tab defines parameters that affect how the device works in the system.  For example, here you can configure the trip and parking detector, the splitting of trips into time segments, and data filtering.

### The Valid flag in raw data

Valid is a field in the raw data of a packet that shows whether the packet is considered reliable for further coordinate processing.

Valid = 0 means the packet is considered unreliable. Such packets are stored in the system but are excluded from processing when tracks, geofences, and other operations that require reliable coordinates are recalculated.

The Valid = 0 mark is assigned in only two cases:

• the packet has no coordinates, or zero latitude or longitude values are transmitted

• the packet falls under the specified filtering formula

After such a packet is saved, its participation in recalculation can no longer be changed: it will not be used when the data is reprocessed.

The filters by the number of satellites, speed, and other parameters from the “Event filtering” block work differently. They are applied dynamically, only during data recalculation. If you change the parameters of these filters and run the recalculation again, the result may change.

For example, if the minimum number of satellites in the object settings is 4, packets with fewer satellites may be excluded when tracks and reports are recalculated. But the packets themselves do not get the Valid = 0 mark.

If you want such packets to be marked as unreliable right away, use a filtering formula. For example: %satsinview% < 4

This formula marks packets where the number of satellites is less than 4 as Valid = 0. These packets are stored in the system but do not participate in the recalculation of tracks, geofences, and other data.
