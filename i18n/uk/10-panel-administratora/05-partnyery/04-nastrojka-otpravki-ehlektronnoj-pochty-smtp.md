-   # У панелі адміністратора перейдіть у розділ «Партнери»
    

![](images/drex_nastrojka_otpravki_ehlektronnoj_pochty__smtp__custom.png)

2\. Двічі клацніть на вибраному партнері — відкриється вікно з налаштуваннями. Виберіть вкладку SMPT.

Вкладка SMTP призначена для налаштування надсилання електронної пошти через зовнішній SMTP-сервер.

![](images/drex_nastrojka_otpravki_ehlektronnoj_pochty__smtp__custom_2.png)

Тут вказуються параметри поштового сервера, через який система надсилатиме сповіщення, рахунки та інші листи.

Параметри налаштування

• SMTP Host — адреса SMTP-сервера

• SMTP Port — порт SMTP-сервера

• SMTP Login — логін для авторизації на поштовому сервері

• SMTP Passw — пароль для авторизації

• SMTP Email — адреса електронної пошти, від імені якої надсилатимуться листи

• Безпека SMTP — вибір типу з’єднання (без шифрування, SSL, TLS — залежно від налаштувань сервера)

Будь ласка, уважно перевіряйте введені дані — від коректності цих налаштувань залежить доставка листів.

## Перевірка SMTP-сервера

Після введення параметрів можна виконати перевірку підключення.

Система використовує протокол SMTP (Simple Mail Transfer Protocol) для тестування з’єднання та авторизації.

Перевірка виконується таким чином:

1\. Система отримує із запиту адресу SMTP-сервера й перевіряє, чи вказано її

2\. Отримує порт підключення. Якщо порт не задано, використовується стандартний порт 25

3\. Створюється екземпляр SMTP-клієнта, налаштовується тайм-аут підключення та рівень налагодження

4\. Виконується спроба підключення до сервера:

— якщо вибрано SSL, до адреси автоматично додається префікс ssl://

— під час підключення по SSL тимчасово вимикається перевірка сертифіката

5\. Після успішного з’єднання надсилається команда EHLO (розширена команда привітання SMTP)

6\. Система отримує список підтримуваних сервером розширень ESMTP

7\. Якщо вибрано режим TLS і сервер підтримує STARTTLS, система:

— ініціює захищене з’єднання

— повторно надсилає команду EHLO

8\. Якщо сервер підтримує автентифікацію, виконується спроба входу з використанням указаного логіна та пароля

### Обробка помилок

Якщо на будь-якому етапі виникає помилка:

— інформація записується в журнал помилок

— повертається HTTP-код 400

— виводиться повідомлення про помилку у форматі JSON

Незалежно від результату перевірки з’єднання коректно закривається командою QUIT.

Насамкінець функція повертає параметри підключення та результат перевірки.

Ця процедура допомагає переконатися, що сервер доступний, підтримує вибраний тип шифрування та приймає вказані облікові дані.

Якщо перевірка не проходить, рекомендуємо перевірити адресу сервера, порт, тип безпеки та дані для входу.
