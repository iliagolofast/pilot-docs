---
title: "Статистика"
---

На вкладці Statistics відображається статистика передавання даних та інформація про можливі помилки ретрансляції.

Щоб відкрити статистику, перейдіть у розділ «Ретрансляція» → «Statistics».

![](images/drex_statistika_custom.png)

Сторінка дає змогу контролювати роботу ретрансляції, відстежувати успішність передавання даних, аналізувати помилки та виявляти проблемні об’єкти або напрямки передавання.

![](images/drex_statistika_custom_2.png)

Статистика формується на основі даних сервісу ретрансляції та відображається з урахуванням прав поточного користувача.

Адміністратор може переглядати глобальну статистику по всій системі або статистику за окремими endpoint.

Користувач-партнер бачить статистику лише за своїми endpoint та endpoint партнерів, що перебувають нижче в його ієрархії.

### Режими перегляду статистики

Для адміністратора доступний фільтр Scope:

-   Global (Глобально) — статистика по всій системі ретрансляції.
    
-   Endpoints (Endpoints) — статистика за окремими напрямками передавання даних.
    

![](images/drex_statistika_custom_3.png)

Користувачі з роллю партнера працюють лише в режимі Endpoints.

## Фільтри статистики

У верхній частині сторінки розташовані фільтри, які дають змогу вибрати необхідні дані для аналізу.![](images/drex_statistika_custom_4.png)

### Scope (Область статистики)

Визначає джерело статистики:

-   Global — статистика по всій системі;
    
-   Endpoints — статистика за окремими endpoint.
    

Доступно лише адміністраторам.

### Protocol (Протокол)

Фільтр за протоколом передавання даних. Дає змогу відображати статистику лише за вибраним протоколом.

### Metric (Метрика)

Визначає, які події відображатимуться в графіках і таблицях.

Доступні такі значення:

-   All metrics — усі метрики
    
-   OK only — лише успішно прийняті пакети
    
-   Errors only — лише помилки
    
-   Spooled only — лише пакети, поміщені в чергу
    
-   Dropped only — лише відкинуті пакети
    

### Endpoint

Дає змогу вибрати один endpoint або групу endpoint для аналізу.

Список endpoint згрупований за партнерами.

### Loop threshold/hour (Поріг циклічного передавання на годину)

Використовується для пошуку об’єктів із підозріло великою кількістю переданих пакетів.

Якщо кількість пакетів перевищує вказаний поріг, об’єкт може потрапити в таблицю Loop suspicion.

### Від і до

Початок і кінець аналізованого періоду.

Час на графіках відображається в локальному часовому поясі користувача в 24-годинному форматі.

## Графіки статистики

У верхній частині сторінки відображаються графіки, які допомагають швидко оцінити стан ретрансляції.

**![](images/drex_statistika_custom_5.png)**

### Traffic over time

Показує зміну кількості пакетів у часі.

Графік допомагає визначити:

— періоди високої активності

— різке збільшення навантаження

— моменти появи помилок

— періоди відсутності передавання даних

### Outcome

Показує розподіл результатів передавання даних.

За графіком можна швидко оцінити:

— скільки пакетів було успішно прийнято

— скільки пакетів завершилося помилкою

— скільки пакетів було поміщено в чергу

— чи є проблеми з передаванням даних

![](images/drex_statistika_custom_6.png)

### By protocol

Порівнює статистику за різними протоколами передавання даних.

Графік дає змогу визначити:

— який протокол використовується найчастіше;

— на якому протоколі виникає більше помилок

— які протоколи створюють основне навантаження

### By endpoint

Порівнює статистику між endpoint.

За графіком можна швидко визначити:

— найактивніші endpoint

— endpoint із підвищеною кількістю помилок

— напрямки передавання з найбільшим навантаженням

Якщо натиснути на будь-який endpoint на графіку By endpoint, система автоматично:

— вибере цей endpoint у фільтрі

— оновить решту графіків

— оновить таблиці статистики

— покаже інформацію лише за вибраним endpoint

![](images/drex_statistika_custom_7.png)

## Метрики

У статистиці використовуються такі показники.

### Accepted / Ack

Кількість пакетів, успішно прийнятих зовнішньою системою. Чим вищий цей показник, тим успішніше працює ретрансляція.

### Send

Кількість спроб надсилання пакетів. Показує загальний обсяг вихідного передавання даних.

### Errors

Кількість помилок надсилання або підключення. Зростання цього показника зазвичай свідчить про проблеми зі зв’язком, налаштуваннями endpoint або доступністю зовнішньої системи.

### Spooled

Кількість пакетів, поміщених у чергу на надсилання. Такі пакети будуть надіслані пізніше, коли передавання стане можливим.

### Dropped

Кількість пакетів, які були відкинуті сервісом і не будуть передані.

### Queue

Поточний розмір черги endpoint. Якщо значення постійно зростає, це може свідчити про проблеми з надсиланням даних у зовнішню систему.

## Таблиці статистики

Під графіками розташовані таблиці з інформацією.

![](images/drex_statistika_custom_8.png)

### Top endpoints

Список endpoint із найбільшою кількістю переданих пакетів за вибраний період.

Дає змогу швидко визначити найактивніші напрямки передавання даних.

### Recent endpoint errors

Список останніх помилок ретрансляції.

Таблиця допомагає швидко зрозуміти причину проблем із передаванням даних і визначити endpoint, у якому виникла помилка.

### Top vehicles for endpoint

Список об’єктів, які створили найбільший обсяг трафіку для вибраного endpoint.

Використовується для аналізу навантаження та пошуку найактивніших об’єктів.

![](images/drex_statistika_custom_9.png)

### Loop suspicion

Список об’єктів, які перевищили встановлений поріг кількості пакетів на годину.

Така ситуація може свідчити про циклічне передавання даних, помилку налаштування обладнання або некоректну роботу інтеграції.

За появи об’єктів у цьому списку рекомендується перевірити налаштування ретрансляції та джерело даних.

![](images/drex_statistika_custom_10.png)
