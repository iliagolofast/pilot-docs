У цій статті наведено вимоги та рекомендації для розгортання PILOT на виділеній інфраструктурі вашої організації.

Інформація призначена для системних адміністраторів, інженерів та інтеграторів, які готують інфраструктуру та підтримують роботу системи.

## Підбір конфігурації сервера

Конфігурація залежить від очікуваного навантаження:

— кількості підключених пристроїв і частоти передавання повідомлень

— кількості одночасних користувачів

— використовуваних звітів та інтеграцій

— строків зберігання даних

— підключених модулів

Базові параметри слугують відправною точкою для промислової експлуатації. Вони не гарантують продуктивність за будь-якого навантаження.

Якщо пристрої передають дані кожні 1–5 секунд, навантаження на процесор, базу даних і диски суттєво зростає. Для такого режиму необхідно заздалегідь провести навантажувальне тестування та передбачити запас ресурсів.

RAID підвищує стійкість дисків до відмов, але не замінює резервне копіювання.

## Зберігання даних

Вихідні події від пристроїв зберігаються в базі даних. Строк їх зберігання визначається налаштуваннями системи та доступним дисковим простором. Зазвичай він не повинен перевищувати трьох місяців.

Під час розрахунку обсягу сховища враховуйте:

-   кількість пристроїв і середню частоту повідомлень
    
-   строк зберігання вихідних подій
    
-   обсяг історії, треків і даних звітів
    
-   вкладення, фотографії та медіафайли
    
-   обсяг і строк зберігання резервних копій
    

Обсяг сховища для резервних копій розраховуйте за розміром повної копії бази даних, кількістю копій, що зберігаються, і використовуваним стисненням. Передбачте запас щонайменше 20%. Фіксований обсяг у 1 ТБ підходить не для кожного встановлення.

Сервер бази даних має перебувати в одній захищеній локальній мережі із сервером застосунків. PostgreSQL, Redis і Memcached не повинні бути доступні з інтернету.

### Зберігання відео

Обсяг відеоархіву залежить від кількості камер, середнього бітрейту, тривалості запису та строку зберігання.

Для попереднього оцінювання використовуйте формулу:

Обсяг, ТБ = кількість камер × середній бітрейт, Мбіт/с × годин запису на добу × днів зберігання × 0,00045 × 1,3

Операційну систему відеосервера вибирають з урахуванням вимог обладнання та його драйверів.

Для нових встановлень використовуйте підтримувану редакцію Windows Server не нижче Windows Server 2019. Розширена підтримка Windows Server 2019 діє до січня 2029 року. Строки підтримки опубліковано на сторінці [Microsoft Lifecycle](https://learn.microsoft.com/en-us/lifecycle/products/windows-server-2019).

## Операційна система та програмні компоненти

Підтримувана платформа — Oracle Linux 8 x86\_64 або образ операційної системи, узгоджений із технічною підтримкою.

До складу встановлення входять:

-   Nginx
    
-   PHP-FPM та необхідні розширення PHP
    
-   PostgreSQL
    
-   Redis
    
-   Memcached
    
-   SocketProxy та обробники повідомлень пристроїв
    
-   фонові завдання та засоби моніторингу
    

Точні версії компонентів визначаються інсталяційним пакетом конкретного релізу PILOT. Не оновлюйте їх вручну без перевірки сумісності та узгодження часу проведення робіт.

### Віртуальне середовище

Розгортання у віртуальному середовищі підтримується за дотримання вимог до ресурсів:

-   процесорні ресурси та пам’ять мають бути зарезервовані
    
-   дискова підсистема має забезпечувати необхідну кількість операцій введення-виведення за секунду — IOPS
    
-   суттєва передпідписка ресурсів віртуальної машини не допускається: виділені ресурси мають бути забезпечені фізичною інфраструктурою

Порти PostgreSQL, Redis і Memcached мають бути доступні лише всередині серверного сегмента.

Для вихідних з’єднань серверу можуть знадобитися:

-   DNS і синхронізація часу NTP
    
-   HTTPS-доступ до репозиторіїв операційної системи та зовнішніх сервісів
    
-   SSH-доступ до gitlab.pilot-gps.com через TCP-порт 22122 для встановлення та оновлень
    
-   доступ до сервісів геокодування, маршрутизації, карт та інтеграцій, підключених у системі
    

Налаштовуйте правила доступу до зовнішніх сервісів за доменними іменами та узгодженими портами, а не за статичними IP-адресами: адреси сервісів можуть змінюватися.

Якщо локальний сервер тайлів карт не розгорнуто, доступ до картографічних ресурсів також потрібен робочим місцям користувачів.

На час встановлення надайте серверу контрольований доступ до необхідних репозиторіїв і сервісів. Необмежений доступ до інтернету не потрібен.

## Резервне копіювання та відновлення

До введення системи в експлуатацію визначте політику резервного копіювання. Вона має включати:

-   резервне копіювання бази даних
    
-   резервне копіювання конфігурації, сертифікатів і налаштувань інтеграцій
    
-   окреме резервне копіювання медіафайлів і відеоархіву, якщо вони використовуються
    
-   зберігання копій поза основним сервером
    
-   шифрування копій і обмеження доступу до них
    
-   регулярну перевірку відновлення
    

Періодичність створення копій і строк їх зберігання визначаються з урахуванням вимог власника системи:

-   RPO — допустимий період втрати даних у разі збою
    
-   RTO — допустимий час відновлення роботи системи
    

Успішне створення резервної копії не підтверджує її придатність для відновлення. Періодично виконуйте тестове відновлення та перевіряйте результат.

## Підготовка до експлуатації

Перед запуском системи необхідно:

1\. Налаштувати TLS-сертифікат для робочого доменного імені

2\. Обмежити доступ міжмережевим екраном: дозволити лише необхідні підключення

3\. Закрити прямий доступ до службових компонентів з інтернету

4\. Налаштувати персональні SSH-облікові записи з автентифікацією за ключами

5\. Забезпечити синхронізацію часу

6\. Налаштувати моніторинг доступності сервісів, вільного місця, навантаження, черг обробки та результатів резервного копіювання

7\. Узгодити час проведення оновлень і визначити відповідальних співробітників

## Доступ для технічної підтримки

Для віддаленої технічної підтримки необхідний захищений SSH-доступ через VPN або проміжний сервер доступу — bastion-host.

Надавайте доступ лише уповноваженим фахівцям, на обмежений строк і з журналюванням дій.

## Що підготувати перед встановленням

Для узгодження встановлення підготуйте:

-   Доменне ім’я, статичну IP-адресу та TLS-сертифікат
    
-   Параметри очікуваного навантаження та список використовуваних модулів
    
-   Перелік протоколів і портів пристроїв
    
-   Мережеві правила та адреси для адміністрування
    
-   Відомості про виділене місце для бази даних, резервних копій і медіафайлів
    
-   Вимоги до RPO, RTO та строків зберігання даних
    
-   Контакти співробітників, відповідальних за інфраструктуру та доступи
    
-   Параметри моніторингу та канал отримання оповіщень
    

## Перевірка після встановлення

Після встановлення проводиться приймання системи. Воно включає перевірку:

— приймання даних від пристроїв

— побудови звітів

— роботи інтеграцій

— роботи моніторингу

— тестового відновлення з резервної копії
